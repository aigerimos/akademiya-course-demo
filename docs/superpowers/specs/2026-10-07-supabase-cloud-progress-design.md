# Академия: Supabase Auth и облачный прогресс

## Цель

Добавить в демо Академии личные аккаунты и синхронизацию учебного прогресса через Supabase. Пользователь сможет продолжать обучение на разных устройствах. Курсы и вопросы остаются в статическом наборе данных приложения.

## Согласованный объём

- Регистрация, вход, выход и сброс пароля по email и паролю.
- Просмотр курсов доступен без входа. Гостевой прогресс по-прежнему хранится локально.
- После входа завершённые уроки и последний результат теста загружаются из Supabase и сохраняются туда.
- При первой авторизации гостевой прогресс переносится в аккаунт: отметки уроков объединяются; уже имеющийся облачный результат теста имеет приоритет над локальным.
- Локальная копия остаётся для быстрого отображения и работы при временном сбое. Интерфейс показывает состояние синхронизации.
- При выходе приложение возвращается в гостевой режим и не показывает локальный кэш предыдущего аккаунта.

## Варианты хранения

Рассмотрены отдельные строки прогресса и единый JSON-документ на пользователя. Выбран реляционный вариант: отдельная запись для каждого урока и последнего результата курса. Это уменьшает риск перезаписи прогресса при работе с нескольких устройств и позволяет ограничить доступ на уровне строк.

## Архитектура

- Клиент остаётся статическим HTML/CSS/JavaScript на Vercel; для Auth и запросов используется официальный Supabase JavaScript-клиент версии 2, подключённый с закреплённой версией через CDN. Сборка и серверные функции не добавляются.
- Email/password Auth управляет регистрацией, сессией и восстановлением доступа. Секреты и service-role key в браузер не помещаются.
- Таблица `academy_progress` хранит `user_id`, тип записи (`lesson` или `quiz`), `course_id`, ключ урока либо `latest`, значение завершения/счёта и время изменения. Уникальность задаётся пользователем, типом записи, курсом и ключом.
- Row Level Security включён. Политики `SELECT`, `INSERT`, `UPDATE` и `DELETE` разрешают доступ только при `auth.uid() = user_id`. Анонимный пользователь не читает и не меняет чужой прогресс.
- URL проекта и публичный publishable/anon key загружаются клиентом из отдельного `supabase-config.js`. Оба значения являются публичной клиентской конфигурацией и могут присутствовать в статическом коде; защита данных обеспечивается RLS, а не сокрытием этих значений.
- Клиентский адаптер загружает облачное состояние при входе, сохраняет изменения асинхронно и обновляет локальную копию немедленно. Ошибки сети не удаляют уже сохранённые локальные отметки и явно показываются пользователю.

## Сценарии и согласование данных

1. Гость читает курсы, отмечает уроки и проходит тесты; данные хранятся в существующем `localStorage`.
2. После регистрации/входа приложение загружает прогресс аккаунта и переносит в него локальные отметки, которых ещё нет в облаке.
3. Если для теста уже есть облачный результат, он остаётся главным; иначе импортируется локальный результат. После объединения интерфейс показывает объединённое состояние.
4. Изменения уроков и результатов теста сразу отражаются в интерфейсе и локальном кэше; облачная запись выполняется через upsert от имени вошедшего пользователя.
5. При сбое запроса данные остаются в браузере, а статус сообщает, что синхронизация ожидает восстановления связи.
6. Выход закрывает сессию и возвращает гостевой прогресс. Кэш аккаунта хранится отдельно от гостевого ключа.

## Настройка и развёртывание

- В репозитории появится SQL-файл с таблицей, ограничениями, индексами и RLS-политиками, а также инструкция по применению его в Supabase SQL Editor.
- Для работы нужны Supabase project URL и публичный publishable/anon key. Их добавляют в `supabase-config.js`, который Vercel раздаёт как статический файл; service-role key не используется приложением и не помещается в браузер или публичный репозиторий.
- В Supabase Auth задаются URL сайта на Vercel и допустимые redirect URL для подтверждения email и сброса пароля.
- Supabase-проект и его ключи сейчас не настроены. Реальный облачный вход и sync можно проверить после создания/выбора проекта и внесения его публичной конфигурации.

## Проверка качества

- Unit-тесты миграции/объединения локального и облачного прогресса, namespace кэша пользователя и проверки записи оценок.
- Проверка локальных сценариев гостя, регистрации/входа/выхода, загрузки прогресса, повторного входа и сетевой ошибки.
- Проверка RLS на двух пользователях: каждый видит и изменяет только собственные строки.
- После настройки Supabase — smoke test в браузере и проверка production-сайта на Vercel.

## Не входит в объём

- Перенос курсов и тестовых вопросов в таблицы Supabase.
- Административная панель редактирования курсов, роли преподавателей, социальный вход и серверные функции.
- Изменение проходного балла или логики оценивания.
