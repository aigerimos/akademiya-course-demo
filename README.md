# Академия

Демо-платформа для коротких курсов по управлению, дипломатии и геополитике. Сайт работает как статические HTML/CSS/JavaScript-файлы без сборки. Курсы доступны гостям; после настройки Supabase можно создавать аккаунт, входить с разных устройств и синхронизировать прогресс.

Опубликованная демо-версия: [akademiya-course-demo.vercel.app](https://akademiya-course-demo.vercel.app/).

## Запуск без облачной синхронизации

Откройте `index.html` в браузере. Отметки уроков и результаты тестов сохраняются в `localStorage` этого браузера. Пока конфигурация Supabase пустая, сайт работает в гостевом режиме.

Для проверки email-переходов запустите локальный HTTP-сервер, например:

```sh
py -m http.server 8000
```

Откройте `http://localhost:8000` и добавьте этот адрес в разрешённые redirect URLs Supabase.

## Подключение Supabase

1. Создайте Supabase project в своём аккаунте.
2. В Supabase откройте **SQL Editor**, вставьте содержимое [`supabase/schema.sql`](supabase/schema.sql) и выполните его. Таблица `academy_progress` включает RLS и политики, ограничивающие каждую операцию строками текущего пользователя.
3. В разделе **Project Settings → API Keys** скопируйте **Project URL** и публичный **Publishable key** (`sb_publishable_…`). Старый публичный `anon` key тоже поддерживается.
4. Откройте [`supabase-config.js`](supabase-config.js) и укажите значения:

   ```js
   const config = {
     url: 'https://YOUR_PROJECT_REF.supabase.co',
     key: 'sb_publishable_YOUR_PUBLIC_KEY',
     redirectUrl: '',
   };
   ```

   Оставьте `redirectUrl` пустым, чтобы использовать домен открытого сайта. Эти URL/key предназначены для клиентского приложения и будут видны посетителям сайта. **Не вставляйте сюда `service_role` key или секретный ключ.** Доступ к прогрессу ограничивается RLS-политиками в базе.
5. В настройках **Authentication → URL Configuration** задайте **Site URL** и добавьте в **Redirect URLs** адрес сайта и локальный адрес разработки, например `https://YOUR_SITE.vercel.app/**` и `http://localhost:8000/**`.
6. Проверьте, что включён email provider в **Authentication → Sign In / Providers**. Если включено подтверждение email, пользователь завершает регистрацию по ссылке из письма. Ссылка для восстановления пароля возвращает его на домен открытого сайта.
7. Откройте сайт по HTTPS на Vercel или через локальный HTTP-сервер. После заполнения конфигурации появятся формы регистрации, входа и восстановления пароля. Вход загружает облачный прогресс и переносит в аккаунт гостевые отметки; облачный результат теста имеет приоритет при объединении.

Изменённый `supabase-config.js` является частью статического сайта. Для публикации в Vercel отправьте коммит в подключённый GitHub-репозиторий либо разверните репозиторий способом, которым обычно обновляете сайт.

## Проверки

Требуется Node.js. Запуск тестов:

```sh
node --test tests/*.test.cjs
```

Проверки покрывают локальный прогресс, объединение гостевых и облачных отметок, auth-адаптер, интерфейс аккаунта и статические RLS-политики. Для полноценной интеграционной проверки настройте реальный проект и проверьте доступ с двумя отдельными пользователями: каждый должен видеть и изменять только собственный прогресс.
