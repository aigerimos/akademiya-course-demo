# Академия

Демо-платформа для коротких курсов по управлению, дипломатии и геополитике. Сайт работает как статические HTML/CSS/JavaScript-файлы без сборки. Гости сохраняют прогресс локально; с аккаунтом Supabase он синхронизируется между устройствами.

Опубликованная демо-версия: [akademiya-course-demo.vercel.app](https://akademiya-course-demo.vercel.app/).

## Запуск без облачной синхронизации

Откройте `index.html` в браузере. Без входа отметки уроков и результаты тестов сохраняются в `localStorage` этого браузера. Для email-входа откройте опубликованный сайт по HTTPS или запустите локальный HTTP-сервер.

Для проверки email-переходов запустите локальный HTTP-сервер, например:

```sh
py -m http.server 8000
```

Откройте `http://localhost:8000` и добавьте этот адрес в разрешённые redirect URLs Supabase.

## Конфигурация Supabase

Этот репозиторий подключён к Supabase-проекту Академии. Таблица [`academy_progress`](supabase/schema.sql) создана с RLS-политиками, ограничивающими операции строками текущего пользователя. Включены email-регистрация и подтверждение адреса.

Клиентская конфигурация находится в [`supabase-config.js`](supabase-config.js). В ней допустимы только **Project URL** и публичный **Publishable key** (`sb_publishable_…`) или старый публичный `anon` key. Они видны посетителям сайта; **никогда не добавляйте сюда `service_role` key или секретный ключ**. Доступ к прогрессу ограничивается RLS-политиками базы.

В Supabase заданы Site URL `https://akademiya-course-demo.vercel.app/` и разрешённые redirect URLs для этого сайта и `http://localhost:8000/**`. Email-провайдер и подтверждение email включены. Для регистрации пользователь открывает ссылку подтверждения из письма; восстановление пароля возвращает его на опубликованный сайт.

При первом входе сайт загружает облачный прогресс и переносит гостевые отметки в аккаунт. Облачный результат теста имеет приоритет при объединении. Для локальной разработки запускайте `py -m http.server 8000`.

Изменённый `supabase-config.js` является частью статического сайта. Для публикации в Vercel отправьте коммит в подключённый GitHub-репозиторий либо разверните репозиторий способом, которым обычно обновляете сайт.

## Проверки

Требуется Node.js. Запуск тестов:

```sh
node --test tests/*.test.cjs
```

Проверки покрывают локальный прогресс, объединение гостевых и облачных отметок, auth-адаптер, интерфейс аккаунта и статические RLS-политики. Для полноценной интеграционной проверки настройте реальный проект и проверьте доступ с двумя отдельными пользователями: каждый должен видеть и изменять только собственный прогресс.
